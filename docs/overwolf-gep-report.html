Overwolf Electron + Game Events (GEP) for Deadlock Coach

Feasibility report · researched 31 Oct 2026 · no code was changed. Sources are linked at the end; everything marked unverified needs a test with the real SDK.

Verdict: technically a strong fit, commercially a hard constraint.

Overwolf's Game Events Provider supports Deadlock in production today, and it supplies exactly the data our screenshot vision struggles with most. That includes every player's health, deaths, souls, level, items and ultimate state, an exact match clock, match start, end and result, and your incoming-damage breakdown. It would fix most of the alive/dead, clock, hero identity, item and end-of-game errors we spent the last reviews on.

It does not give map positions, the Rift, Urn, Midboss, Rejuvenator, structures by lane or respawn timers, so the screenshot vision stays necessary for macro coaching.

The catch is distribution. As of 1 November 2026, Overwolf only approves apps that integrate Overwolf ads or Tebex subscriptions. Apps must be listed and distributed through the Overwolf Appstore, and private personal-use apps are not approved. That conflicts with the current "free, local, GitHub Pages" model.

1. What GEP gives us for Deadlock

Deadlock (game id 24482) is listed as supported for Overwolf Electron. Overwolf's public status endpoint reports the game as published, enabled for Electron, all features healthy, with minimum GEP version 314.2.4.

3. What it would look like

ow-electron app (Windows) ├─ main process: app.overwolf.packages.gep │ setRequiredFeatures(['game_info','match_info']) │ on('new-info-update' | 'new-game-event') ──► normalise to GameSnapshot fields │ (hero_status, clock, items, result…) ├─ renderer: the existing web app (web/dist) unchanged in spirit │ screen capture (desktopCapturer) ─► WASM vision ─► minimap, Rift, Urn, Midboss… │ merge: GEP fields win where present ("observed"), vision fills the rest └─ optional: Overwolf overlay window (in-game), owadview ad slot (required for approval)

Most of the codebase carries over. The Rust engine, the rules and the snapshot schema stay as they are, with GEP becoming a second, more reliable evidence source. That matches our rule "never claim unobserved evidence": GEP fields would carry their own provenance.

4. Constraints and risks

Monetization (hard)From 1 Nov 2026 apps must integrate Overwolf ads and/or Tebex subscriptions. Third-party monetization isn't allowed. Payouts are NET 60 with a $200 minimum.
Distribution (hard)Apps must be listed and distributed through the Overwolf Appstore. Private apps for personal use are not approved, and public distribution outside Overwolf isn't permitted. An older FAQ entry says you can host anywhere; the newer monetization page overrides it.
Windows onlyGame events, overlay and recording are Windows-only for now. Mac/Linux get ads only.
Closed source runtimeow-electron is a closed-source Electron fork that updates its packages every few hours; a package update needs an app restart.
Code signingYou need your own code-signing certificate from a commercial CA (DigiCert, Sectigo…).
Data can go downFeatures can be disabled after a game patch or at the studio's request. Apps must check the status endpoint and fall back. We already have that fallback: vision.
Start orderGEP must register as the game launches. Starting mid-match can lose events, so the app should say so.
Privacy / analyticsUsage analytics are on by default (can be reduced to a minimum). With ads come a consent manager and Overwolf's privacy policy. The "nothing leaves your browser" promise would change.
Valve's stanceUnverified: how GEP reads Deadlock and whether Valve has commented on it. Overwolf lists the game in production, but check this before shipping to players.

5. Options

6. Recommendation

  1. Don't switch platforms now. The approval rules (ads/subscriptions, Appstore-only) are a product decision for you, not a technical one.
  2. If you want to explore it, do a time-boxed spike first (option C, about 1–2 days). Run the official sample app on the GEP dev channel and log the Deadlock feed for two matches next to a screenshot recording. Check: update rate of roster, health while dead, whether souls is net worth, and incoming_damage when the panel is open.
  3. Design for it either way. Keep the snapshot "evidence source" idea so a GEP adapter could fill hero_status, game_clock_secs, items, match_result without touching the rules.
  4. Decide on option B only after the spike, and with the monetization model chosen.
